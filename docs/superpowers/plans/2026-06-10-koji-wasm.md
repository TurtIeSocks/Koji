# koji-wasm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a browser-loadable, multithreaded WASM build of Koji's clustering algorithm for a demo/portfolio, without disturbing the native server/CLI builds.

**Architecture:** Add a `native` feature (default-on) to the `algorithms` crate that gates the wasm-hostile deps (`sysinfo`, `koji-plugins`, filesystem/`chrono` debug helpers). Keep `rayon` and run it on real browser threads via `wasm-bindgen-rayon`. Swap `std::time::Instant` for `web-time` on the clustering hot path. A new thin `crates/koji-wasm` cdylib exposes a typed `cluster()` entry point (tsify DTOs ↔ koji-core types). Host on Vercel (COOP/COEP headers).

**Tech Stack:** Rust 2024, `wasm-bindgen`, `wasm-bindgen-rayon`, `serde-wasm-bindgen`, `tsify`, `web-time`, `wasm-pack`, nightly + `-Z build-std`.

**Spec:** `docs/superpowers/specs/2026-06-10-koji-wasm-design.md`

**Invariant for every task:** the native default build stays byte-for-byte behaviorally identical. After any task that edits `algorithms`/`macros`, `cargo build` and `cargo test` on the workspace must stay green.

```rust
//! Wasm-boundary DTOs. tsify derives generate the TypeScript `.d.ts` interfaces;
//! `serde` drives (de)serialization across the JS boundary. These mirror a flat,
//! demo-friendly subset of `koji_core::ClusteringConfig`.

use serde::{Deserialize, Serialize};
use tsify::Tsify;

/// Clustering request. `points` is `[[lat, lng], ...]`.
#[derive(Tsify, Deserialize)]
#[tsify(from_wasm_abi)]
pub struct ClusterRequest {
    pub points: Vec<[f64; 2]>,
    pub radius: f64,
    pub min_points: usize,
    pub max_clusters: usize,
    /// "fastest" | "balanced" | "fast" | "better" | "best" | "honeycomb"
    #[serde(default = "default_mode")]
    pub cluster_mode: String,
    /// "radius" | "s2"
    #[serde(default = "default_calc")]
    pub calculation_mode: String,
    #[serde(default)]
    pub center_clusters: bool,
}

fn default_mode() -> String {
    "balanced".to_string()
}
fn default_calc() -> String {
    "radius".to_string()
}

/// Clustering result: cluster centers + a stats summary.
#[derive(Tsify, Serialize)]
#[tsify(into_wasm_abi)]
pub struct ClusterResponse {
    pub clusters: Vec<[f64; 2]>,
    pub stats: StatsSummary,
}

/// Demo-facing subset of `algorithms::stats::Stats`.
#[derive(Tsify, Serialize)]
#[tsify(into_wasm_abi)]
pub struct StatsSummary {
    pub total_points: usize,
    pub points_covered: usize,
    pub total_clusters: usize,
    pub cluster_time_ms: f64,
}
```

- [ ] **Step 2: Write the conversion layer**

Create `crates/koji-wasm/src/convert.rs`. Both `ClusterMode` and `CalculationMode` implement `Deserialize` from a bare string, so reuse that via `serde_json::Value::String` rather than hand-matching:

```rust
//! DTO ↔ koji-core conversions. This is the single validation boundary between
//! untyped JS input and the typed algorithm.

use koji_core::{
    CalculationMode, ClusterMode, ClusteringConfig, S2Config, SingleVec,
};
use wasm_bindgen::JsError;

use crate::dto::{ClusterRequest, ClusterResponse, StatsSummary};

/// Parse a string into a koji-core enum via its existing `Deserialize` impl.
fn parse_mode<T: serde::de::DeserializeOwned>(s: &str, what: &str) -> Result<T, JsError> {
    serde_json::from_value::<T>(serde_json::Value::String(s.to_string()))
        .map_err(|e| JsError::new(&format!("invalid {what} '{s}': {e}")))
}

impl ClusterRequest {
    /// Split into the point list + the koji-core config the algorithm consumes.
    pub fn into_core(self) -> Result<(SingleVec, ClusteringConfig), JsError> {
        let mode: ClusterMode = parse_mode(&self.cluster_mode, "cluster_mode")?;
        let calculation_mode: CalculationMode =
            parse_mode(&self.calculation_mode, "calculation_mode")?;
        let cfg = ClusteringConfig {
            mode,
            radius: self.radius,
            min_points: self.min_points,
            max_clusters: self.max_clusters,
            cluster_split_level: 0,
            calculation_mode,
            s2: S2Config::default(),
            center_clusters: self.center_clusters,
            genetic_post_processing: false,
            plugin_args: String::new(),
        };
        Ok((self.points, cfg))
    }
}

impl ClusterResponse {
    /// Build the response from the cluster centers + the populated `Stats`.
    pub fn from_parts(clusters: SingleVec, stats: &algorithms::stats::Stats) -> Self {
        ClusterResponse {
            stats: StatsSummary {
                total_points: stats.total_points,
                points_covered: stats.points_covered,
                total_clusters: stats.total_clusters,
                cluster_time_ms: stats.cluster_time as f64 * 1000.0,
            },
            clusters,
        }
    }
}
```

> Note: `Stats.cluster_time` is seconds (`Precision`). If a field name or unit differs once verified against `crates/algorithms/src/stats.rs`, adjust the mapping here — the field set surfaced is `total_points`, `points_covered`, `total_clusters`, `cluster_time`.

```rust
pub use dto::{ClusterRequest, ClusterResponse, StatsSummary};

/// Cluster `points` under `req`'s parameters. Returns centers + stats, or a
/// `JsError` on invalid input.
#[wasm_bindgen]
pub fn cluster(req: ClusterRequest) -> Result<ClusterResponse, JsError> {
    let (points, cfg) = req.into_core()?;
    let mut stats = algorithms::stats::Stats::new("wasm".to_string(), cfg.min_points);

        features: vec![],
        foreign_members: None,
    };
    let clusters = algorithms::clustering::main(&points, &cfg, collection, false, &mut stats);
    Ok(ClusterResponse::from_parts(clusters, &stats))
}
```

## Task 9: Build to wasm and resolve residual gating

This is a build-fix loop: the `--no-default-features` host build (Task 5 Step 6) is a strong proxy, but the real `wasm32-unknown-unknown` target can surface dep-level breakage (a transitive crate that does not compile to wasm). Apply the rule table per error.

**Rule table (error → fix):**

| Compile error mentions | Fix |
|---|---|
| `std::fs` / `File` / `create_dir_all` | `#[cfg(feature = "native")]` the function/call (debug only) |
| `sysinfo` / `System` | add `#[cfg(feature = "native")]` + a wasm fallback constant |
| `koji_plugins` / `PluginKind` / `JoinFunction` | `#[cfg(feature = "native")]` the import/arm; non-plugin path falls back |
| `Instant` panic risk (no compile error) | swap that file's import to `web_time::Instant` |
| a transitive crate fails to build for wasm | gate the module that uses it native-only if off the clustering path; otherwise find a wasm-compatible alternative and note it |
| `getrandom` "js feature on non-wasm" | already target-gated; ensure it is under `[target.'cfg(target_arch = "wasm32")'.dependencies]` |

```rust
//! Headless-browser smoke test. Native `cargo test` skips this file (cfg gate).

use koji_wasm::{cluster, ClusterRequest};
use wasm_bindgen_test::*;

wasm_bindgen_test_configure!(run_in_browser);

#[wasm_bindgen_test]
fn clusters_a_small_grid() {
    let points: Vec<[f64; 2]> = (0..20)
        .map(|i| [35.0 + (i as f64) * 0.001, 139.0 + (i as f64) * 0.001])
        .collect();
    let n = points.len();
    let req = ClusterRequest {
        points,
        radius: 200.0,
        min_points: 1,
        max_clusters: 0,
        cluster_mode: "fastest".to_string(),
        calculation_mode: "radius".to_string(),
        center_clusters: false,
    };
    let res = cluster(req).expect("cluster() should succeed");
    assert!(!res.clusters.is_empty(), "expected at least one cluster");
    assert_eq!(res.stats.total_points, n, "all points accounted for");
}
```
